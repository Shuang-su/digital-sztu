# 执行计划

1. 核对升级分支、现有改动、真实执行进程与数据库状态，保护原始批次。
2. 保留查询和分页缩小机制；对可恢复 GraphQL 失败最多增加三次重试，等待 5、15、45 秒，重放同一查询和游标。
3. 认证、限流和服务端 Retry-After 不进入普通重试；保存服务端边界，继续保留中断、空间不足与重试耗尽后的恢复能力。
4. 在标准错误提供有界重试反馈；不改变最终标准输出 JSON。
5. 隔离验证分页重放、不重复提交、重试上限、认证和限流、中断及磁盘不足；运行全量单元测试和公开交付检查。
6. 保存 checkpoint 并推送现有升级分支；验证远端 CI，从同一研究数据库恢复，监测实际进度。保持 PR 草稿，不提前正式入库或发布。
