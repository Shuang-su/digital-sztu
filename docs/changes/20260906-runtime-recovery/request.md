## 3. 核心优化：让完整普查能够稳定推进

保留现有“正式 JSON／Markdown + 研究 SQLite + 可重建视图”的架构，集中优化研究执行器。

- 减少队列扫描。将操作类型筛选和批量上限放进 SQL，补齐状态、类型、优先级及排序所需索引；状态汇总使用索引或轻量聚合。迁移必须事务化，保留所有旧操作、分页断点和审计信息。
- 增加过程反馈。为 `discover resume` 增加可选进度输出，展示本批完成数、新增操作、剩余操作、证据复核项、限流状态及可恢复时间。最终 `--json` 结果继续写到标准输出，过程信息写到标准错误，保持脚本兼容。
- 完善中断恢复。Ctrl+C、网络错误、限流及磁盘不足时，保留已提交页，回滚未完成事务，并给出明确的恢复命令，避免只留下异常堆栈。
- 提高证据复核效率。将待审项目的原文定位、校园关联依据、fork 差异和证据缺口集中呈现；缺失 README 的项目进入替代证据复核，不通过自动排除来减少队列。
- 保留完成标准。继续执行规则内的关系扩展及一层未知账号桥接；工具账号的扩展边界按已有规则处理。只有可执行队列、必要分页和证据复核结束，才开展两轮定向补漏并判断是否可入库。

这里应衡量每批实际推进量、重试量和复核积压。由于研究会继续发现新线索，不展示误导性的固定总量完成百分比。
