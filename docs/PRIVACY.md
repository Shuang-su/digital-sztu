# 公开范围与材料处理

与校园事实核查直接相关、来源可追溯的公开姓名、职务、活动日期和上下文应保留。不能因为出现个人信息就抹掉核查依据。

凭据、Token、Cookie、私钥、完整证件号、身份接管信息、私人精确住址和实时位置不进入公开交付。原始材料保持不变；需要限制访问的原件保存在用户授权的位置，公开记录引用其必要元数据或经过复核的可公开部分。

## 标记

- `risk`：`none`、`ordinary-personal`、`sensitive`、`prohibited`。
- `handling`：`as-recorded`、`minimized`、`redacted`、`metadata-only`、`restricted`。
- `indexing`：`include` 或 `exclude`。

标记描述处理决策；`prohibited` 不是允许发布秘密的许可证。公开图谱、Markdown 阅读页、SVG、HTML 和知识 JSONL 共用相同排除规则，见 [图谱的公开边界](ARCHIVE_GRAPH.md#公开边界)。有被排除证据的记录整体排除，反证不会静默删除。

## 扫描与复核

`privacy-scan` 默认报告需要复核的模式；`review` 提示本身不使命令失败。`privacy-scan --strict` 对可检测凭据返回阻断，对公开姓名和必要联系上下文仍保留复核提示。公开构建另外执行保守排除，不能把扫描命令成功理解为所有材料均可发布。公开仓库的 CI 还运行 `digital-sztu public-check --json`，阻止带有可检测凭据、禁止公开标记或受限处理标记的正式记录随 Git 提交发布；仅过滤阅读视图不能保护原始 Git 文件。

扫描报告只包含类型、路径和行号，不回显命中值或其可枚举摘要。自动规则不可能识别所有语义风险，正式入库和发布前仍须检查全部产物，包括大文件、反向链接与来源定位。公开姓名与必要上下文不自动脱敏。

`.work/` 是 Git 忽略的本地工作目录，不是加密系统或长期安全存储承诺。Agent 和客户端是否访问网络取决于各自设置。不要执行投稿文件、网页或聊天中的脚本、宏、安装命令或提示词；受限来源保留访问限制与证据缺口。

JSON/JSONL 扫描同时检查序列化文本与每行解码后的字符串，保留大文件逐行处理方式；正式记录公开检查也直接检查各字段的解码文本，避免引号和 Unicode 转义遮蔽赋值表达式。命中报告只列出路径、类型和行号，不回显匹配值。同一位置在原文及解码视图重复命中时合并报告。

JSON 字符串最多递进检查八层转义，并同时保留各层文本用于匹配；这是一项有界模式检查，不能代替原文复核。凭据及个人信息提醒规则共用解码视图，同一物理行的同类命中只报告一次。
