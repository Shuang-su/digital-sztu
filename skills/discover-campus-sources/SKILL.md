# Campus source discovery

Read `docs/DATA_MODEL.md`, `docs/FACT_CHECKING.md`, `docs/PRIVACY.md` and `docs/DISCOVERY.md`. Work from the user's archive repository, never a plugin cache. Confirm the requested campus and source scope from the session; preserve already authorized choices.

1. Inspect `digital-sztu discover status --json` and the existing run before starting. Initialize only when no database exists. For old surveys, use `discover init --legacy-state <state.json>`; preserve original files and record their hashes. The default SQLite database is `.work/discovery/state.sqlite3`.
2. Establish explicit public seeds with `discover seed --name owner/repo` or a public account. Resume bounded batches with `discover resume --limit 100 --progress --json`. Batches are execution quanta, not a survey completion limit. Run `status` after interruption; retained page cursors and stable IDs are authoritative.
3. Inspect individual candidates with `discover inspect --id <stable-id> --json`. Read the actual README or primary source around each cited location; keyword hits, stars, follows, account affiliation and GitHub repository creation dates do not prove a campus project, student identity or project release date.
4. Review `relevance-review`, missing README, external and scoped contributor queues. Submit explicit decisions and evidence through `discover review --file <reviews.json>`. For missing README, inspect linked documentation, source files or official pages; preserve any unresolved gap. A fork requires evidence for the campus-specific delta; only expand accounts mapped to those changes, never every upstream contributor.
5. Follow explicit source references. Use available web search and read-only browser tools for relevant official sites, project pages and course material. Add discovered URLs with `discover external --file <candidates.json>`, then review them. Restricted access stays documented; never bypass access controls or execute downloaded source code. Public names and necessary context remain; credentials and identity-takeover information do not enter public output.
6. The social bridge is bounded: a confirmed anchor A may expose unknown B; B may expose one further layer C. C's self material can be screened, but further social expansion requires independent campus evidence. Preserve all unread candidates and necessary pagination; do not mark them excluded merely to empty the queue.
7. After all executable queues and evidence reviews are resolved, run a targeted `discover sweep --file <queries.json>`, resume and review every result, then `discover sweep --complete`. Complete two consecutive rounds with no newly confirmed relevant project; cover campus name variants, course terms, known project/topic gaps and station-external references in the accompanying reviewed report. An incomplete or truncated search cannot count as a no-new round.
8. Export the private sources ledger, operations, graph, audit and report with `discover export`. Inspect all outputs, including large files. Report exact pending, restricted, missing and pagination counts. `partial` is never described as complete.
9. Once `promotion_ready` is true, prepare explicit Source and Knowledge Record records with claims, source locators, unknown validity where appropriate, and research-to-canonical mappings. Create Event or Node only when evidence supports that kind of record. Use `discover promote --file <promotion.json>`; the CLI validates in isolation, preserves existing files and makes repeated identical imports idempotent.
10. Run `digital-sztu check --json`, unit tests and two deterministic builds. Inspect archive graph, SVG and Markdown reading pages for the same content revision, accurate evidence, no candidate leakage and working links. Follow the user's Git and publishing authorization; ordinary research does not itself authorize publication.

For evidence-reviewed tool or automatic attribution accounts, `discover review` accepts `expansion_exclusion: "tool-attribution-account"` with a scope reason and public evidence. Stop only their unfinished following/followers expansion; preserve completed lists, original cursors and counts, contribution evidence and all previously discovered candidates. Do not infer this classification from a username alone. Re-encountering or renaming an account must not reopen the exclusion.
